## 💡 【導師講義：標籤與作用域的真相】

### 1. 勇者的三種標籤貼紙 (const, let, var)
我們把變數想像成你要帶進副本的「物資」，首先我們要選擇適合它的標籤：

*   **`const` (國家強力膠標籤)**：**首選！** 標籤一旦貼上，物品就嚴禁更換、嚴禁重貼（不可重新賦值）。
*   **`let` (區域姓名貼)**：非常有原則。雖然標籤內容可以更換，但它嚴禁離開它所屬的房間 `{ }`。
*   **`var` (不受控的穿牆術)**：古老的遺物。它的眼裡沒有牆壁，經常會從房間滲透到野外，導致地標資訊大混亂。勇者辛梅爾已經不再使用它了。

> **導師的圖解心法：** 觀察下面這張領地圖，你就能明白為什麼 `var` 會讓工程師抓狂，而 `let/const` 又是如何守護我們的房間門 `{ }`。

## 🛖 【營火叮嚀：為什麼標籤會亂飛？】
> 很多新手覺得 `var` 改成 `let` 只是換個名字。不，這是一場關於 **「預測性」** 的革命。
> 如果一個物資不該變，它就絕對不能變。如果它只屬於這個封閉房間，它就不該跑去外面鬧事。當你用 `var` 時，標籤會在沒人注意時「提昇 (Hoisting)」到半空中，讓你明明還沒宣告標籤卻能抓到它（抓到 undefined，這就是通靈的來源！）。

## ⚔️ 【演武場：從冒險者到勇者辛梅爾】

### 招式示範：宣告語法與作用域領地

#### ❌ 冒險者：不受控的穿牆術 (var)
```javascript
if (true) {
    var treasure = "神祕寶藏"; // 在房間內貼標籤
}
console.log(treasure); // 🛡️ 居然在房間外也能印出？牆壁消失了！
```

#### ✅ 勇者辛梅爾：守規矩的區塊管理 (let/const)
```javascript
if (true) {
    let map = "隱藏地圖"; // 在房間內貼標籤
}
// console.log(map); // ❌ 報錯！地圖在房間消失了，這才符合邏輯。
```

> **導師講評：** 你看，勇者的寫法明確定義了「資源的生存邊界」。這能防止那種「改了 A 卻壞了 B」的悲劇發生。**預設全用 const**，非變動不可才用 `let`，這是目前公會最強大的生存法則。

---

#### ⚠️ 【實戰雷區：避開那些致命陷阱】
> **1. 給錯標籤的空窗期 (TDZ)**：不要以為有了 `let` 就能隨便宣告。如果你在標籤還沒宣告前就想用它，會遇到「暫時死區（Temporal Dead Zone）」，直接噴錯給你看。
> **2. `const` 標籤不能留白**：跟 `let` 不同，你貼上 `const` 標籤的瞬間就必須賦予它價值，不能寫 `const a;`。
> **3. `typeof null` 的世紀大 Bug**：請記住，當你對 `null` 進行類型鑑定時會得到 `"object"`。這是 JS 誕生以來就留下的遠古漏洞（公會也拿它沒轍），請把它當成常識背下來。

## 🏰 【勇者精英課：不可變性的種子】
為什麼公會如此強調 `const`？
在未來的「大型團隊冒險（某個強大的現代開發框架）」中，我們極度強調 **「不可變性 (Immutability)」**。
當一個資料被宣告為 `const`，我們就能放心地在程式的其他地方使用它，而不必擔心某個路過的隊友偷偷改了它。**「減少變數的變動」是讓程式碼從「生鏽」變為「神兵」的關鍵。**

---

## 📝 【夥伴筆記：今日修煉精華】
##### *這份筆記是你的隨身護身符，卡關時看一眼，真相就在裡面。*
- **標籤三選一**：優先用 `const` 穩定物資，非變動不可才用 `let`，徹底埋葬 `var`。
- **作用域守衛**：記得 `{ }` 就是牆壁。`let/const` 是守法公民，不會隨便穿牆。
- **鑑定勝過通靈**：隨時使用 `typeof` 觀察型別，防範 `typeof null === 'object'` 的歷史陷阱。
