### 1. 勇者的物資管理：三種標籤貼紙
我們把變數想像成你要帶進副本的「物資」，首先我們要來貼標籤（宣告）：

1. var：不受控的穿牆標籤 (Old School)
「這標籤太不受控了，連傳說中的勇者——辛梅爾都不再使用了。」
```javascript=
if(副本地圖){
    var treasureChest ="神祕的寶貝";
}
console.log(treasureChest); // 神祕的寶貝
```
>特性：
>牆壁是透明的：它的眼裡沒有區塊圍牆 `{}`。你以為標籤貼在副本裡，它卻直接滲透到野外。
>無法預測：因為它會亂跑，你隨時可能在沒想到的地方看到這張標籤，導致地圖資訊混亂。

2. const：國家核發的強力膠標籤 (首選)
「勇者都喜歡 const，因為它最守規矩，最不會讓地圖出亂子。」
```javascript=
if (新手村) {
    const 傳家寶 = "生鏽的鐵劍";
    // 傳家寶 = "屠龍刀"; // ❌ 報錯！國家不允許更改
}
// console.log(傳家寶); // ❌ 報錯！出了村子標籤就消失了
```
>特性：
防偽防改：強力膠等級，標籤與物品生死相依，貼上後嚴禁重貼（不可重新賦值）。
保密防諜：具有嚴格的區域限制。
新手村的標籤，出了村子連個影子都抓不到，絕對不會外流。

3. let：區域限定的姓名貼 (靈活)
「很有原則的標籤。雖然可以重貼，但絕對不離開它被貼上的房間。」
```javascript=
if (副本地圖) {
    let 副本專用武器 = "新手木棒";
    
    // 使用魔法石改造（重新貼標籤）：
    副本專用武器 = "鋼鐵長劍（副本專用）"; 
}
// console.log(副本專用武器); // ❌ 報錯！這張標籤在門口就自動銷毀了
```
>特性：
認房不認人：它是區域限定的。你在旅館裡貼的標籤，到了野外沒人認得。
可重複使用：雖然不能帶出房間，但只要還在房間內，你可以隨意把標籤撕下來換貼到不同的裝備上。

#### ⚔️ 勇者的標籤選用指南

| 標籤類型 | 冒險者的態度 | 適合情境 | 實際案例 |
|----------|------------|----------|----------|
| **const** | 堅定不移，絕不動搖 | 1. 預設使用的首選標籤<br>2. 固定的環境設定<br>3. 賦值後就不會換掉的物資 | 1. 使用者名稱 (`userName`)<br>2. 圓周率 (`PI`)<br>3. 資料庫連線字串 |
| **let**   | 靈活調整，隨時進化 | 1. 數值會隨時變動的計數器<br>2. 需要升級、更換的裝備<br>3. 迴圈中的暫時變數 | 1. 勇者年紀 (`age`)<br>2. 錢包存款 (`gold`)<br>3. 副本迴圈計數器 (`i`) |
| **var**   | 古老遺物，避而遠之 | 1. 處理百年前的古老遺產 (Legacy code)<br>2. 維護前輩留下來的舊地圖<br>3. 除非別無選擇，否則絕對不碰 | 1. 舊版專案的全域設定<br>2. 你祖父時代的程式碼 |

## 2. 給物資標籤取個好名字：公會命名規範

在勇者的世界裡，每個物資上的標籤都是為了讓其他勇者（或是未來的妳）能快速理解物資的用途，公會統一使用 **「小駝峰命名法 (camelCase)」**。

### 📜 公會命名規範：別讓妳的標籤變成詛咒

在冒險中，好的名稱就像是在地圖上標示清楚的座標；壞的名稱則會讓隊友在戰鬥中（維護程式時）陷入混亂。

---

### 🏷️ 命名基本規則
- **格式**：第一個單字全小寫，之後的每個單字首字母大寫。  
- **視覺印象**：這叫 **小駝峰命名法 (camelCase)**，因為單字中間突起的地方就像駱駝的背。  
- **範例**：`heroName`、`potionCount`、`currentMapLevel`

---

### 📜 公會強烈建議的命名公式

| 公式類型 | 使用情境 | 範例 | 勇者的直覺反應 |
|----------|----------|------|----------------|
| **形容詞 + 名詞** | 描述物品的狀態或種類 | `isGoldenSword` | 「這是一個是非題，答案只有是或否。」 |
| **動詞 + 名詞** | 描述一個動作或獲取過程 | `getWeaponDamage` | 「這是一個動作，執行後會給我傷害數值。」 |
| **複數名詞** | 描述一整袋、一整群的物資 | `enemyLists` | 「裡面不只一個，是一群敵人的資料。」 |

---

### ✍️ 標籤宣告的四大元素

在冒險者的世界裡，宣告標籤就是正式向公會登記：「這是什麼東西，它歸誰管」。

---
#### 標籤類型 (Keyword)
- **功能**：決定標籤的性質。  
- **選擇**：是焊死的強力膠 `const`？還是可以重貼的姓名貼 `let`？  
- **勇者提醒**：辛梅爾說過，絕對不要使用會穿牆的 `var`。  
---
#### 標籤名稱 (Identifier)
- **功能**：妳為物資取的「小駝峰式」好名字。  
- **要求**：名字必須具備說明書的功能，讓人一眼看出內容物。  
---
#### 等號 = (Assignment Operator)
- **功能**：這是動作，不是結果！  
- **意義**：代表「賦值 (Assignment)」，意思是把右邊的物資，貼上左邊的標籤。  
- **想像**：妳拿著一張標籤，把它「啪」地一聲貼在右邊的物品上。  
---
#### 分號 ; (Terminator)
- **功能**：代表這道魔法指令（語句）的終結。  
- **意義**：告訴 `JavaScript` 引擎：「這張標籤我註冊完了，請看下一條指令」。
- **勇者提醒**：辛梅爾的建議，每一段程式最後加上`;`才是好勇者。  
---

```javascript
// 標籤類型   標籤名稱   =   物資內容;
   const     heroName   =   "辛梅爾";
```
![image alt](https://i.meee.com.tw/kIOS4qE.png)
### ❌ 冒險者的禁忌（反面教材）
如果妳不想被公會除名，請絕對避開以下行為：

- **意義不明的標籤**：`var a = 10;`  
  勇者 OS：a 是什麼？是黃金？是等級？還是魔王的剩餘血量？別讓隊友猜謎！
- **語言混亂**：`let xiaoTuoFeng = "..."`  
  勇者 OS：雖然這也是小駝峰，但公會通用語是英文，請別挑戰隊友的語文能力。
- **法規禁區 (語法錯誤)**：`const 1stWeapon = "..."`  
  法規限制：JavaScript 引擎不認得數字開頭的標籤，會直接引發魔法爆炸（Syntax Error）。

---

### 💡 冒險者的命名哲學
好的標籤名稱應該要讓你 **「不看內容也知道裡面裝什麼」**。
- **Bad**: `const data = "辛梅爾";` （太模糊，誰知道這是名字還是遺物？）  
- **Good**: `const legendaryHeroName = "辛梅爾";` （精確、優雅且充滿敬意）

## 3. 物資鑑定：認識不同的資料型別

在冒險者的世界裡，並非所有的物資都能用同一種方式處理。
在貼上標籤前，我們必須先鑑定物資的「型別」。

---

### 💎 基礎三大型別
「配合課程這邊只是先列舉最常使用的型別，進階知識捲軸的部分還有更詳細的介紹。」

| 物資型別 | 專業名稱 | 形象比喻 | 範例 |
|----------|----------|----------|------|
| **字串** | String | 魔法卷軸：用來紀錄名字、對話或描述 | `"辛梅爾"`、`'新手木棒'` |
| **數字** | Number | 金幣與數值：用來計算血量、傷害或錢 | `100`、`-50`、`3.14` |
| **布林值** | Boolean | 機關開關：只有「開」或「關」兩種狀態 | `true` (真) / `false` (假) |

---
這三種型別就像冒險的基礎物資，掌握它們，妳才能在程式世界裡正確地使用和加工資源。
### 💎 勇者的鑑定術：`typeof`
「不靠通靈寫程式」的第一條準則是：**隨時確認妳手上的東西是什麼。** 
公會提供了一招基礎鑑定咒語：`typeof`。
> **為什麼要鑑定型別？因為你不能對『麵包』使出『磨利術』。數字可以加減乘除，但文字只能拼接拉長。**


```javascript
const item = "聖劍";
console.log(typeof item); // 輸出："string" (字串)

const level = 99;
console.log(typeof level); // 輸出："number" (數字)

const isClear = true;
console.log(typeof isClear); // 輸出："boolean" (布林值)
```

> **導師叮嚀：** 養成習慣，當妳的鍊金術（運算）結果不如預期時，第一步就是掏出 `typeof` 對著變數照一下。真相往往就藏在型別的細節裡。




## 4. 資料加工：鍊金術與魔法卷軸

收集到物資後，可以透過「加工」讓它們發揮更大的威力。

### 🧪 基礎鍊金術（四則運算）

#### 🧪 數字型標籤煉金術

>`+` (融合)
```javascript=
let exp=10; //冒險者現在的經驗值是10

//打了一隻強力的哥布林

//經驗值增加200

exp=exp+200; //公會提供的標準寫法

exp+=200; //勇者辛梅爾提供的寫法

```
> 勇者的寫法也是從基礎而來，冒險者可以任意選擇自己喜歡的寫法

>`-` (消耗)：扣除血量或支付代金
```javascript=
let hp=100; //冒險者現在的血量是100

//被一隻路過的哥布林摸了一下

//扣了10滴血

hp=hp-10; //公會提供的標準寫法

hp-=10; //勇者辛梅爾提供的寫法
```

>`*` (加成)：計算暴擊傷害或加倍獎勵
```javascript=
let atk=20; //冒險者現在的攻擊力是20

//路上受到天使的祝福，增加1.5倍攻擊力


atk=atk*1.5; //公會提供的標準寫法

atk*=1.5; //勇者辛梅爾提供的寫法
```

>`/` (分配)：平均分配戰利品
```javascript=
let equipmentCount = 10; // 發現寶箱中有 10 件裝備

equipmentCount=equipmentCount/5; //公會提供的標準寫法

equipmentCount /= 5; //勇者辛梅爾提供的寫法
```

>`%` (剩餘)：（鑑定剩餘物資）
```javascript=
//分配物資時，如果無法整除，剩下的那些「零頭」就是用 % 來計算的。
let totalPotions = 10; // 總共有 10 罐藥水
let teamMembers = 3;   // 隊伍有 3 個人

// 進行分配...
let leftPotions = totalPotions % teamMembers; 
console.log(leftPotions); // 剩下 1
```
### 🧪 字串型標籤煉金術
>字串型的煉金術比較神奇，除了 `+` (融合)之外，其餘的`-` (消耗)、`*` (加成)、`/` (分配)、%` (剩餘)，javascript 都會嘗試將字串轉成數字然後進行處理，這邊先示範給各位冒險者看
```javascript=
let a='10';
let b='5';

console.log(a-b); // 5
console.log(a*b); // 50
console.log(a/b); // 2
console.log(a%b); // 0
```
>當字串進行`+` (融合)時，Javascript 雖然會優先進行轉型，但只要 `+` 兩邊是字串，則不轉型 
```javascript=
let a='10';
let b='5';
console.log(a+b); // 105
```
>以上情況也適用在數字型及字串型混和使用時

### ⚠️ 鍊金術失效：NaN (Not a Number)
並非所有的字串都能被成功轉化成數字。如果你丟進去的是真正的「文字描述」，鍊金術就會失敗。

```javascript
let a = "10";
let b = "哥布林";
console.log(a - b); // 輸出：NaN
```


### 📜 魔法卷軸（字串模板 Template Literals）
在處理完數值鍊金後，我們需要寫出一份優雅的戰報。這時就要使用比 `+` 號拼接更先進的 **字串模板**。

- 使用 **反引號 `` ` ``** 包裹文字（在鍵盤數字 1 的左邊）。  
  > **記得喔！反引號位於數字 1 的左邊，按下去就好，不要按到 Shift 或其他組合鍵！**
- 使用 `${}` 嵌入標籤。  

```javascript
const heroName = "辛梅爾";
const enemy = "哥布林";
const damage = 200;

// ✅ 現代勇者的優雅報告 (字串模板)
const battleReport = `🛡️ 勇者 ${heroName} 對 ${enemy} 造成了 ${damage} 點傷害！`;

// ❌ 舊時代的辛苦拼接 (字串融合)
// const oldReport = "🛡️ 勇者 " + heroName + " 對 " + enemy + " 造成了 " + damage + " 點傷害！";
```

在 JavaScript 的世界裡，字串模板就像魔法卷軸，能讓訊息更清晰、更安全。

- 結構清晰
就像直接在卷軸上填空，不需要被一堆 `+` 和引號搞混。
- 自動轉型
`${}` 裡面的物資不管是什麼型別，魔法卷軸都會自動幫妳把它轉成「文字」顯示，非常安全。


## ⚔️ 【實戰演武場】

### 綜合招式：冒險者的戰報合成
我們將今天學到的所有標籤與鍊金術，融合成一份真正的戰報。請注意觀察，當原本的「數字」被誤貼成「字串」標籤時，會發生什麼慘劇：

```javascript
// 1. 使用 const 焊死不變的標籤
const heroName = "辛梅爾";
const baseAtk = 50;

// 2. 使用 let 宣告會變動的標籤
let extraDmg = "10"; // ⚠️ 注意！這是不小心的「字串」標籤

// 3. 鍊金術與轉型鑑定 (第一次嘗試)
let totalDmg = baseAtk + extraDmg; 
console.log(`鑑定結果：${totalDmg} (型別：${typeof totalDmg})`); 
// 輸出：鑑定結果：5010 (型別：string) -> ⚠️ 發生轉型陷阱了！攻擊力變成了奇怪的字串

// 4. 修正後的鍊金術
extraDmg = 10; // 撕下舊標籤，換上真正的數字標籤
totalDmg = baseAtk + extraDmg;
const finalReport = `🛡️ 勇者 ${heroName} 最終造成的總傷害為：${totalDmg}`;
console.log(finalReport);
// 輸出：🛡️ 勇者 辛梅爾 最終造成的總傷害為：60
```

> **導師講評：** 這就是實戰。妳需要同時掌握標籤的生存區域、命名規範以及鍊金時的轉型風險。只有透過 `console.log` 的持續觀測（不靠通靈），妳才不會在複雜的副本中被神祕的 `"5010"` 給搞糊塗。

## 📜 【修煉精華：冒險者筆記】

- **標籤三選一**：優先用 `const` 穩定物資，非變動不可才用 `let`，徹底埋葬 `var`。
