## 💡 【導師講義：影印術的兩大必殺技】

### 1. 打破容器的「爆破術」
展開運算子 `...` 的動作極其簡單：它就是把原本裝在「陣列」或「物件」裡的舊物資全部「倒出來」，放在空中供你重新運用。

```javascript
const oldScrolls = ["火球術", "治癒術"];

// ✅ 影印術：變出一個新木箱 []，再把舊捲軸 ... 倒進去
const newScrolls = [...oldScrolls, "傳送術"]; 

console.log(newScrolls); // ["火球術", "治癒術", "傳送術"]
console.log(oldScrolls); // ["火球術", "治癒術"] (原版毫方無傷，連結已斷開！)
```
![Day 06：展開運算子的影印魔法](https://i.meee.com.tw/nU2a5NZ.jpg)
> **導師的圖解心法：** 
> 想像 `oldScrolls` 是一個舊木箱。若用 `const copy = oldScrolls`，那只是在舊箱子貼上兩個標籤。
> 但用 `[...oldScrolls]`，則是先把舊箱子拍碎（`...`），讓捲軸飄在空中，再用一個剛打造好的新箱子（`[]`）把捲軸接住。這就是 **「純淨複製」**。

---

### 2. 資料重組的「合併與覆蓋」
影印術最強的地方在於，你可以在合併的瞬間，對資料進行「進化」。

```javascript
const baseSkill = { category: "魔法", mp: 10 };
const fireball = { name: "火球術", mp: 50 };

// ✅ 兩組合併：後面的內容會蓋掉前面的内容 (Overwriting)
const superFireball = { 
    ...baseSkill, 
    ...fireball, 
    level: "Max" 
};

console.log(superFireball); 
// { category: "魔法", name: "火球術", mp: 50, level: "Max" }
```

> **導師叮嚀：** 你注意到 `mp` 了嗎？後面的 `fireball` 因為有同樣的屬性名，會直接「覆蓋」掉前面的 `baseSkill`。這種「後蓋前」的規則，在未來你處理 **「冒險者狀態更新」** 時，簡直是呼吸般的必備技能！

## ⚔️ 【演武場：從冒險者到勇者辛梅爾】

#### ❌ 冒險者：吃力的「手動接龍」
如果你想把兩支小隊合併，以前可能要寫迴圈，或是用比較囉唆的 `concat`：

```javascript
const teamA = ["戰士", "法師"];
const teamB = ["牧師", "弓箭手"];

// 雖然能運作，但寫法不夠直覺
const fullTeam = teamA.concat(teamB); 
```

#### ✅ 勇者辛梅爾：極致優雅的陣列合併
使用影印術（展開運算子），就像把兩個麻袋直接打開倒進大麻袋一樣：
```javascript
const teamA = ["戰士", "法師"];
const teamB = ["牧師", "弓箭手"];

// 輕輕一揮，兩軍集結！
const fullTeam = [...teamA, ...teamB]; 
```

---

#### ⚠️ 【實戰雷區：避開那些致命陷阱】
> **小心「淺層影子」與提貨券！**
> 展開運算子 `...` 就像公會的影印機，它雖然會幫你印出一份新的「大箱子」。但如果原本的箱子裡放的是 **「保險箱提貨券（指標）」**，它影印出來的依然是 **同一張提貨券**，上面寫著同一個地址。
>
> ```javascript
> const hero = { name: "辛梅爾", bag: { coin: 10 } };
> const clone = { ...hero }; // 影印了大箱子，也影印了提貨券
>
> clone.bag.coin = 999; // ⚠️ 雖然大箱子是新的，但提貨券指向「同一個保險箱」！
> ```
> 
> 當你拿著副本的提貨券去改了保險箱裡的錢（`clone.bag.coin`），原版 `hero` 拿提貨券去看，發現裡面的錢也被改掉了。這就是所謂的 **「淺拷貝 (Shallow Copy)」** —— 只印了外皮，裡面的靈魂（巢狀物件）還是連在一起的。
>
> 💡 **導師的緊急咒語**：如果你非得要在今天就解開這種「深層靈魂連結」，你必須往更深處去影印：
> `const clone = { ...hero, bag: { ...hero.bag } };` 
> 但如果今天有 100 層該怎麼辦？別擔心，我們在下週的 **【深拷貝與序列化】** 魔法課會傳授終極禁咒。

> 🛡️ **架構師的防禦護盾：null 會報錯嗎？**
> 你可能會擔心：如果我要 `{...hero}` 但 `hero` 剛好還是 `null`（例如資料還沒從雲端下載完），會噴錯嗎？
> **答案是：不會！** 在物件展開（Object Spread）中，`null` 與 `undefined` 會被優雅地忽略掉。這是一個非常強大的「自動防禦魔法」，讓你的程式介面更不容易因為資料還沒準備好而崩潰。

## 🏰 【勇者精英課：麻袋收集器】
 
> ⚠️ **前方高能預告**：如果你剛學會三顆點點就覺得有點頭暈，那是正常的。接下來的連動技是為準備晉升「大魔導師」的人準備的範式，看不懂沒關係，先去演武場練練手感也行！

### 其餘參數 (Rest Parameters)：剩下的都進口袋！
除了「倒出來」，`...` 還有另一個身份——把它放在函式的「參數接收處」，它就像一個萬能口袋。

> 🌟 **導師小啟發**：還記得 **Day 04** 的解構魔法嗎？當時我們是一個一個取，現在有了 `...`，就能把剩餘的內容一次裝袋！這招正是解構魔法的終極完成體。

#### ❌ 冒險者：吃力的舊時代遺產 (`arguments`)
> **導師碎碎念**：如果你從沒聽過 `arguments`，那恭喜你，你是被新時代眷顧的幸運兒！可以直接學勇者的這招。在沒學會 `...others` 前，前輩們必須用一個「長得像陣列但不是陣列」的神祕物件來抓捕資料，非常吃力且不直覺。*(重點是，在現代流行的「箭頭函式」中，arguments 是完全抓不到東西的！)*

```javascript
function captureLoot() {
    // 必須手動用索引 [0], [1] 去抓，且無法直接使用 map 或 filter 等陣列大招
    console.log(arguments[0]); 
}
```

#### ✅ 勇者辛梅爾：無限大的口袋 `...others`
現在只要在參數最後加上 `...`，剩下的戰利品就會自動乖乖排好，變成一個乾淨的陣列：

```javascript
function captureLoot(firstGold, ...others) {
    console.log(`首獎金幣：${firstGold}`);
    console.log(`剩餘物資袋：`, others); // others 自動變成真正的陣列
}

captureLoot("100G", "魚干", "生鏽鐵劍", "老舊地圖");
```

### 隱藏連動技：解構與其餘參數的「完美合體」
這是架構師最愛用的神技！還記得 **Day 04** 的解構嗎？當我們「取出」特定的屬性後，剩下的可以一次打包（Rest）起來送去其他地方。

```javascript
const treasureChest = { 
    id: 1, 
    quality: "SSR", 
    gold: 500, 
    potion: 10 
};

// 🌟 提取最重要的 id，剩下的內容全部裝進「乾淨資料袋 (...info)」
const { id, ...info } = treasureChest;

console.log(id);   // 1
console.log(info); // { quality: "SSR", gold: 500, potion: 10 } (不包含 id 的純淨資料包)
```

> **導師的實戰點點名**：想像你要把冒險者的「個人檔案」傳給伺服器，但你想把「密碼」漏掉。用這招，你只要解構出密碼，剩下的 `...others` 就是你需要的乾淨資料包了！

## 📝 【夥伴筆記：今日修煉精華】
- **斷開連結**：使用 `const copy = [...arr]` 或 `{...obj}` 建立新副本，避免副作用。
- **後蓋前**：合併時，後面的屬性會覆蓋前面的，這是資料更新的核心。
- **其餘參數**：在函式接收處使用 `...`，能捕捉不限數量的資料，取代舊時代的 arguments。
