# 🛡️ 《JS 核心重構：勇者轉職傳說》世界觀設定

## 1. 核心世界觀：傳奇冒險者公會 (The Remaster Guild)
*   **背景**：
    在「Web 開發」大陸上，有無數的初級勇者想要拿起傳說中的神兵利器 **「React 聖劍」**。然而，聖劍的力量太過強大，若沒有紮實的 **「JavaScript 原力」** 作為基礎，勇者將會被聖劍的能量反噬（噴出滿坑滿谷的 Bug 與白屏）。
*   **公會角色**：
    *   **導師**：公會裡最資深的傳奇工程師，負責揭開 JS 的底層真相，並發布 30 天的轉職任務。
    *   **讀者 (冒險者)**：渴望在 30 天內脫胎換骨、成功轉職的見習勇者。
*   **終極目標**：
    在第 30 天，讓勇者能親手「重鑄」他們的任務佈告欄，正式成為具備 React 戰力的專業開發者。

## 2. 冒險進行方式：30 天的修煉迴圈
每一天，讀者來到公會（你的部落格）都會經歷以下流程：
1.  **領取委託 (Reading)**：讀者在「公會佈告欄」看到今天的任務標題。透過 **【公會任務：RPG 劇情設定】** 進入情境。
2.  **解構真相 (Understanding)**：導師透過 **【視覺化原理拆解】** 指引讀者看透代碼的底層邏輯，消除「程式靠通靈」的畏懼。
3.  **演武重構 (Practice)**：在 **【代碼演武場】** 比較「雷包寫法」與「專家寫法」，建立對 ES6+ 的極致品味。
4.  **埋下種子 (Foreshadowing)**：在文章末尾，導師會給出一條 **「高手直覺」**。讀者現在雖然看不懂，但這實際上是未來神兵的核心觀念。
5.  **執行任務 (Executing)**：讀者必須在 **【公會佈告欄：本日任務執行】** 提供的 CodePen 連結中，完成任務並繳交鑑定報告。

## 3. 公會運行的三大守則 (SoP)
1.  **禁提 Boss 的真名**：在第 28 天之前，絕對不直接提到「React」或「Hooks」等名詞。保持最強烈的懸念。
2.  **視覺最優先**：每一篇任務都**必須**搭配一張圖解圖。如果沒有圖，讀者就看不見真相（原理）。
3.  **不講廢話，只講實踐**：不鑽研過時的 JS 歷史概念，每一章都要回歸到「這招在現代開發中怎麼用才穩健」。

```text
  │     ├── /Phase1_Start (Day 01-07)

```
