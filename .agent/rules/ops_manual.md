# 每日文章撰寫規劃指南

## 1. 每一篇文章的架構
- **標題**：直接使用 `計劃書.md` 內已定好的標題。
- **【公會任務：RPG 劇情設定】**：建立本篇的 RPG 比喻情境，讓讀者代入角色。
- **【導師的：課前叮嚀】**：痛點情境，先講讀者會遇到的坑與為什麼要學這招。
- **【導師講義：視覺化原理拆解】**：圖解與故事，用 Excalidraw 解釋底層邏輯（記憶體、執行序等）。
- **【代碼演武場：Before vs. After】**：雷包寫法與優雅寫法的對照，強調代碼美學。
- **【高手直覺：隱藏的 React 伏筆】**：揭示這一招如何在未來 React 的世界中化為核心動力。
- **【勇者精英課：現代開發架構】**：深入探討本日技術在大型專案中的實踐模式，並引導至更高階的延伸學習。
- **【勇者筆記：今日修煉精華】**：條列式總結本篇核心重點，作為進入實作前的最後複習清單。
- **【公會佈告欄：本日任務執行】**：提供一個具備視覺回饋的 CodePen 互動練習，讓讀者親手完成今日的公會任務。

## 2. 怎麼樣針對主題做圖解
- 工具統一使用 Excalidraw 保持手繪感。
- 畫圖重點：記憶體指向、執行順序、資料流向。
- 儲存路徑：`/Posts/[階段名]/images/`

## 3. 每天主題的關鍵知識點
- **參考與核心來源**：撰寫前必須詳閱 `每日文章發想筆記.md` 內的當日定義。
- **必備三元素**：
    1. **核心關鍵字**：本篇必須釐清的核心術語。
    2. **RPG 比喻**：將抽象邏輯實體化的遊戲設定。
    3. **React 伏筆**：為未來開發留下的關鍵直覺。
- **避坑提醒**：面試最愛考的易錯點與底層陷阱。

## 4. 專案目錄結構與發布規範 (The Remaster Pipeline)
為了維持 Repo 的整潔與確保文章品質，請遵循以下流程：

### 🛠️ 生產線配置
- **草稿沙盒 (Drafts)**：`_doc/drafts/DayXX.md`
    - *說明*：所有新文章與複審修正皆在此目錄進行。
- **正式發布 (Production)**：`Posts/[階段名]/DayXX.md`
    - *說明*：僅存放通過團隊鑑定後的完成品。

### 🚀 發布標準作業程序 (Publishing SOP)
1. **完成撰寫**：在 `_doc/drafts/` 生成初稿。
2. **品質鑑定**：`@Reviewer` 通過術語檢查，`Testers` 通過讀者鑑定。
3. **執行發布指令**：
    - 使用 `@Team Publish DayXX` 觸發自動發布。
    - 檢查檔案編碼是否為 `UTF-8`。
    - 將檔案從 `_doc/drafts/` 移動至 `Posts/[階段名]/`。
    - 更新 `_doc/state/TODO.md` 中的進度。
    - 執行 Git Commit 進行存檔。

## 5. 視覺化圖解 (Excalidraw) 風景定義
為了減少讀者的認知負擔，建立統一的視覺語意：
- **黃色 (#FFD43B)**：代表「資料」(變數值、字串、物件內容)。
- **藍色 (#4DABF7)**：代表「記憶體/空間」(Scope 區域、記憶體方塊)。
- **紅色 (#FA5252)**：代表「執行箭頭/指向」(this 的指向、記憶體參考指標)。
- **手寫字體**：保持手繪感，關鍵字加粗。

## 6. CodePen 實作規範 (勇者實驗室)
- **CSS 基礎**：每一份練習都要載入基本的 `reset.css` 與一個漂亮的無襯線字體 (如 Inter 或 Noto Sans)。
- **操作回饋**：盡量避免只用 `console.log`，設計一個簡單的畫面元素來呈現結果，讓讀者「看得到」回饋。

## 7. 產出前自我檢核表 (Checklist)
- [ ] 標題使用 `計劃書.md` 內定標題。
- [ ] 遵守「去術語化」原則，沒有在第一段丟出天書名詞。
- [ ] 至少包含一張符合色彩規範的「原理邏輯圖」。
- [ ] CodePen 連結已測試，且具備視覺化回饋。
- [ ] Markdown 格式與存放路徑符合規範。
