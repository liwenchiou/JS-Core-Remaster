# 每日文章撰寫規劃指南

## 1. 每一篇文章的架構 (十大區塊)
- **標題**：直接使用 `計劃書.md` 內已定好的標題。
- **【📜 這裡的修煉規則】**：確立當日實作機制與師徒契約（置於頂部）。
- **【🛡️ 公會委託：RPG 冒險標題】**：沉浸式劇情情境，引出本日主題。
- **【💡 導師講義：圖解底層真相】**：Excalidraw 視覺化原理分析。
- **【🛖 營火叮嚀：導師的經驗談】**：開發痛點與「為什麼要學」的情感共鳴。
- **【⚔️ 演武場：從冒險者到勇者辛梅爾】**：Before vs. After 對比。
- **【⚠️ 實戰雷區：避開致命陷阱】**：高階避坑清單，不限新手。
- **【🏰 勇者精英課：邁向職人的進階架構】**：深度知識與架構思維（取代伏筆）。
- **【📝 夥伴筆記：今日修煉精華】**：條列式奧義總結。
- **【🎯 公會佈告欄：交付本日任務】**：CodePen 實作與 QuestBoard 報到。

## 2. 怎麼樣針對主題做圖解
- 工具統一使用 Excalidraw 保持手繪感。
- 畫圖重點：記憶體指向、執行順序、資料流向。
- 儲存路徑：`/Posts/[階段名]/images/`

## 3. 每天主題的關鍵知識點
- **參考與核心來源**：撰寫前必須詳閱 `每日文章發想筆記.md` 內的當日定義。
- **必備三元素**：
    1. **核心關鍵字**：本篇必須釐清的核心術語。
    2. **RPG 比喻**：將抽象邏輯實體化的「公會訓練」設定。
    3. **職人思維**：針對現代開發架構的深度延伸知識。
- **避坑提醒**：面試最愛考的易錯點與底層陷阱。

## 4. 專案目錄結構與發布規範 (The Remaster Pipeline)
為了維持 Repo 的整潔與確保文章品質，請遵循以下流程：

### 🛠️ 生產線配置
- **草稿沙盒 (Drafts)**：`_doc/drafts/DayXX.md`
    - *說明*：所有新文章與複審修正皆在此目錄進行。
- **正式發布 (Production)**：`Posts/[階段名]/DayXX.md`
    - *說明*：僅存放通過團隊鑑定後的完成品。

### 🚀 發布標準作業程序 (Publishing SOP)
1. **完成撰寫**：在 `_doc/drafts/` 生成初稿。
2. **品質鑑定**：`@Reviewer` 通過術語檢查，`Testers` 通過讀者鑑定。
3. **執行發布指令**：
    - 使用 `@Team Publish DayXX` 觸發自動發布。
    - 檢查檔案編碼是否為 `UTF-8`。
    - 將檔案從 `_doc/drafts/` 移動至 `Posts/[階段名]/`。
    - 更新 `_doc/state/TODO.md` 中的進度。
    - 執行 Git Commit 進行存檔。

## 5. 視覺化圖解提示詞 (Diagram Prompts) 規範
為了讓導師能產出風格統一且專業的圖解，在產出草稿時，必須針對該篇主題生成一份 **「Excalidraw 產圖提示詞」**。提示詞需遵循以下視覺語意：

- **核心配色與象徵**：
    - **黃色 (#FFD43B)**：代表「資料與物資」(如變數值、字串內容、物件屬性值)。
    - **藍色 (#4DABF7)**：代表「記憶體與區域」(如 Scope 領域、記憶體方塊、存放容器)。
    - **紅色 (#FA5252)**：代表「流程與能量指向」(如 this 的指向、記憶體參考指標、函數執行的箭頭)。
- **手繪風格定義**：
    - 指定使用「Excalidraw 手繪感 (Hand-drawn look)」。
    - 關鍵術語需加粗，並在提示詞中特別標註「字體較大」。
- **提示詞架構清單**：
    1. **元素清單**：列出圖中需要出現的所有 RPG 物件與對應技術物件。
    2. **配色指示**：明確標註哪些零件要塗上 #FFD43B, #4DABF7 或 #FA5252。
    3. **佈局描述**：說明物件的相對位置（例：左邊是變數盒，右邊是記憶體池）。

## 6. CodePen 實作規範 (勇者實驗室)
- **CSS 基礎**：每一份練習都要載入基本的 `reset.css` 與一個漂亮的無襯線字體 (如 Inter 或 Noto Sans)。
- **操作回饋**：盡量避免只用 `console.log`，設計一個簡單的畫面元素來呈現結果，讓讀者「看得到」回饋。
