# RFC-002：教學守衛：天數邊界校驗 (Curriculum Guard v1.0)

## 🎯 目的
針對 2026-03-19 執行的兩系列重大錯誤（解答外流、提早提到 React、術語超綱）進行系統化防禦。根據 PDCA 原則，「Act」階段必須優化底層 Skill 並強化公會憲章。

## 🔍 問題診斷
1.  **盲目生成**：AI 在生成 CodePen 時，會自動「完成」邏輯，而非「保留」邏輯。
2.  **檢核點缺失**：現有的 `article-reviewer` 專注於結構，忽略了對「尚未教學的內容」進行黑名單過濾。

---

## 🛠️ 優化提案

### 1. 優化 `article-reviewer` Skill
在「檢查項目」中新增：
- **[ ] 教學天數守衛 (Curriculum Guard)**：強制對照 `TODO.md` 或 `計劃書.md`。嚴禁提到「目前天數 + 1」之後的所有術語。例如 Day 08 嚴禁出現 `.map()`、`.filter()`、`Promise` 等字樣。
- **[ ] 黑名單過濾 (Framework Blacklist)**：在 Day 28 前，若文章中偵測到 "React"、"Hooks"、"useState"、"Effect"、"Component" 等字樣，判定為「鑑定失敗」。

### 2. 優化 `codepen-generator` Skill
在「執行指令」中新增：
- **[ ] 零解答鎖定 (Zero-Answer Lock)**：所有 `/* ✍️ 作答區 */` 必須為空，僅允許「情境引導註解」。
- **[ ] 去預測化**：不得在註解中明確標記 `預期輸出 90` 等解答暗示。

### 3. 公會憲章 v2.2 升級修正
在 `agent.md` 的「核心身分」中強化：
- 新增：**「時間管理大師：教學進度不准跑」**。AI 在進行審閱時，必須先 `view_file` 查閱 `計劃書.md` 的目前進度。

---

## 📈 預期效果
- 減少導師手動糾錯的頻率。
- 確保學員在一張「單純、符合等級」的地圖中循序漸進。
- 徹底貫徹「隱形轉職 (Shadow Transformation)」的核心理念。
