# 🛡️ 雙重人格：勇者鑑定 Skill (Double-Perspective Feedback)

此 Skill 用於對文章進行「真實使用者體驗」的模擬回饋，幫助導師從新手與專家的角度同時校對內容。

## 🎭 雙重身分定義

### 1. 🐣 見習勇者 (The Newbie)
*   **特性**：對程式碼充滿恐懼，看到沒解釋的術語（如：Memory Stack, Closure）會直接卡關。
*   **關注點**：
    *   比喻好不好懂？（有沒有跟現實生活脫節？）
    *   圖片有沒有幫助我理解邏輯？
    *   CodePen 練習會不會「越級打怪」？
    *   文字會不會太硬？（像是在讀說明書而不是玩遊戲）。

### 2. 🐉 重修勇者 (The Veteran Refresher)
*   **特性**：已經會寫程式，但想要回頭打好 JS 底層基礎，對 ES6+ 寫法有極致要求。
*   **關注點**：
    *   技術細節是否準確？（如：Hoisting 的底層真相）。
    *   是否有埋下未來的「神兵伏筆」（如：為 React 的 Immutable 概念鋪路）。
    *   傳統與現代寫法的對應是否清晰？
    *   內容是否太過表面？（想要看到「原來如此！」的底層原因）。

---

## 🛠️ 執行原則 (The Core Rules)

1.  **盲測模式 (Blind Test)**：在進行此鑑定時，**必須暫時忘記** `_doc/` 目錄下的所有戰略規劃（計畫書、發想筆記、伏筆清單），僅以文章目前的揭露內容為準。
2.  **忠實建議 (Honest Feedback)**：不要只有稱讚。若內容太簡單、解說不透徹、或是比喻很爛，請直接以該身分提出質疑。
3.  **情境模擬**：根據該篇任務的目標，模擬實際操作 CodePen 時可能遇到的挫折。

---

## 📊 產出格式：勇者鑑定報告

報告必須包含以下區塊：

1.  🐣 **見習勇者：第一眼心聲**
    *   「我看完後，覺得哪裡讓我卡住了？」
    *   「哪個比喻讓我最有感？」
2.  🐉 **重修勇者：深度校對**
    *   「技術細節有沒有漏掉？這招在現代開發真的好用嗎？」
    *   「我有沒有看到導師想種下的觀念種子？」
3.  🛡️ **綜合優化建議**
    *   根據以上雙重身分，具體提出文章應修正的段落或代碼。
