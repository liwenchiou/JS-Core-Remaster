# 🛡️ 雙重人格：勇者鑑定 Skill (Double-Perspective Feedback) v2.0

此 Skill 用於對文章進行「真實用戶體驗」的模擬回饋。v2.0 強化了「章節守衛」與「認知負載」控制，防止過度技術化而導致的無休止修正。

## 🎭 雙重身分定義

### 1. 🐣 見習勇者 (The Newbie)
*   **特性**：對程式碼充滿恐懼，對新術語的「連鎖反應」極度敏感。
*   **鑑定基準 (The Newbie Check)**：
    *   **比喻感**：這個比喻是否能讓我「秒懂」？是否跟現實生活有聯想？
    *   **認知梯度 (Cognitive Ladder)**：這篇知識點是否超過了我「昨天」知識範圍的 **2 個階梯**？（如果一次給太多，我會直接卡關）。
    *   **視覺引導**：圖片提示詞是否解決了我看文字時的腦內霧霾？
    *   **實作門檻**：CodePen 的任務描述是否清晰？我有沒有可能因為沒解釋清楚的細節而挫折？

### 2. 🐉 重修勇者 (The Veteran Refresher)
*   **特性**：已有經驗，正在重塑 JS 魂，極度要求「基礎地基」的穩度與「慣用法」的優雅。
*   **鑑定基準 (The Veteran Check)**：
    *   **80/20 法則**：這篇介紹的是否為實戰中 **80% 時間會用到的核心神技**？若是邊際案例，是否應該移至補充或伏筆？
    *   **地基穩健性**：是否會讓讀者養成未來難以糾正的「壞習慣」？（例如：誤以為傳址可以隨便改）。
    *   **現代化標竿**：是否符合 ES6+ 通行的 Coding Style？對未來架構（如狀態管理）的種子是否埋得正確？
    *   **深度適中**：是否為了追求技術正確（Edge Cases）而破壞了整體的學習流暢度？

---

## 🛠️ 執行原則 (The Core Rules)

1.  **盲測模式 (Blind Test)**：在鑑定時，**必須暫時忘記** `_doc/` 目錄下的戰略計畫。
2.  **章節守衛 (Chapter Guard)**：若一個技術建議需要超過 5 層背景知識才能解釋清楚，請判定為 **「超綱 (Over-teaching)」**，並將其移動至「未來伏筆」區。
3.  **不完美之美 (Beautiful Imperfection)**：適時允許「對新手友善的小簡化」，只要它不導致未來的技術崩壞。

---

## 📊 產出格式：勇者鑑定報告

報告必須包含以下區塊：

1.  🐣 **見習勇者：第一眼心聲**
    *   「有沒有哪裡讓我突然想關掉視窗（認知過載）？」
    *   「這篇教的跟我昨天的連動感如何？」
2.  🐉 **重修勇者：地基校對**
    *   「這招 80/20 法則合格嗎？地基打得穩不穩？」
    *   「哪個技術細節是『點到為止』的藝術？」
3.  🛡️ **綜合優化建議 (Actionable Steps)**
    *   明確指出哪些是「現在必修」，哪些是「未來伏筆」。
