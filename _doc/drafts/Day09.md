## 💡 【導師講義：圖解底層真相】

### 1. 陣列魔法的三大職位
現代陣列方法（Higher-order functions）的核心思維是：**「告訴陣列你要什麼結果，而不是教它怎麼走路。」**

#### 🛠️ 職位說明：
*   **`forEach()`：傳令兵**。就像一個幫你跑腿的士兵，對名單上每個人執行一次特定的「副作用」（比如印出 log），但不會產生新名單。
*   **`filter()`：篩選機**。根據規則（條件），只讓符合資格的人留下來，產生 **「過濾後的新名單」**。
*   **`map()`：加工廠**。讓每個人都進去整型、換裝。產生 **「人數一樣多，但樣子變了的新名單」**。

> **導師的圖解心法：** 觀察下面的生產線。`filter` 就像是一個篩網，刷掉不合格的礦石；而 `map` 就像是一台加工機，把每一塊礦石都打磨成發光的寶石。

## 🛖 【營火叮嚀：為什麼寫 for 迴圈的人常踩雷？】
> 導師看過太多冒險者因為 `i <= array.length` 還是 `i < array.length` 這種小細節，導致整個咒語崩潰。
> 
> **「細節越多，陷阱越多。」** 使用 `map` 或 `filter` 的最大好處，就是你完全不需要管那個該死的 `i` 是多少。這不僅讓程式碼更乾淨，最重要是它體現了 **「不可變性 (Immutability)」**：原版資料永遠不動，我們產出的永遠是新的、乾淨的結果。這在未來你處理「React 狀態重繪」時，是存活的關鍵。

## ⚔️ 【演武場：從冒險者到勇者辛梅爾】

### 招式示範：全自動戰鬥報告 (Chaining Operations)

#### ❌ 冒險者：手動搬運工人 (for loop)
```javascript
const monsters = [10, 50, 5, 80]; // 血量清單
const dangerMonsters = [];

for (let i = 0; i < monsters.length; i++) {
  if (monsters[i] > 20) {
    dangerMonsters.push(`危險等級：${monsters[i]}`);
  }
}
```

#### ✅ 勇者辛梅爾：生產線鏈式連發 (Map + Filter)
```javascript
const monsters = [10, 50, 5, 80];

// 1. 篩選有血量的怪物 (filter) 
// 2. 將數值包裝成勇者報告 (map)
const dangerReports = monsters
  .filter(hp => hp > 20)           
  .map(hp => `🛡️ 回傳：發現強敵！血量為 ${hp}`);     

console.log(dangerReports); 
```

> **導師講評：** 你看，勇者的寫法讀起來就像在讀人類的指令：「過濾大於 20 的，然後轉成報告」。這就是 **「聲明式 (Declarative)」** 程式碼的威力。

---

#### ⚠️ 【實戰雷區：避開那些致命陷阱】
> **1. 忘記回傳 (Missing Return)**：這是在 `map` 與 `filter` 裡最常發生的「沈默悲劇」。如果你在大括號 `{ }` 裡忘記寫 `return`，結果會出現一堆 `undefined`。記得 Day 03 學過的 **「極速吟唱 (Implicit Return)」** 嗎？省略大括號的一行代碼能幫你省去許多麻煩。
> **2. 副作用 (Side Effects)**：在加工過程中悄悄去改動外界的變數，這會讓生產線變得不純淨。生產線應該只負責輸出新產品，不該去弄髒外面的環境。

## 🏰 【勇者精英課：終極鍊金術 reduce()】
如果你想把一整袋名單的資料 **「歸納、縮減」** 成一個具體的東西（比如總血量、或是一張複雜的統計表），那你需要 `reduce()`。
這招是全能的，它不論是過濾、加工還是計算總和，都能一招完成。在 React 深層資料流的處理中，它是大師級的必備武器。

## 📝 【夥伴筆記：今日修煉精華】
##### *這份筆記是你的隨身護身符，卡關時看一眼，真相就在裡面。*
- **forEach()**：點名，不做名單更動。
- **filter()**：篩選。名單變短，保留符合條件的人。
- **map()**：加工。名單長度不變，每個人的「長相」重新定義。
