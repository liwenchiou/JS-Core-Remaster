## 💡 【導師講義：圖解底層真相】

### 1. 短路判斷 (Short-circuiting)
[在 JS 的邏輯運算中，它非常「懶惰」。如果前面的條件已經足夠決定結果，它就根本不會去執行後面的代碼。]

*   **&& (且)**：只要前面是 `false`，後面就連看都不看。
*   **|| (或)**：只要前面是 `true`，後面就直接略過。
*   **?? (空值合併)**：專門對付 `null` 或 `undefined`。

> **導師的圖解心法：** 想像這是一組連環陷阱。`&&` 是「通行證」，只有通過第一關才能領第二關獎勵；`||` 是「備胎」，第一關爆胎了才換二號上場。

## 🛖 【營火叮嚀：導師的經驗談】
> 很多新手會把 `||` 當成設定預設值的神機。但小心！如果你有一筆資料攻擊力剛好是 `0`，而你寫了 `atk || 100`，這隻史萊姆的攻擊力會莫名其妙變成 100。這就是我們為什麼在現代 JS 中更推崇 `?? (Nullish coalescing)` 的原因，它只在資料「真的沒收到」時才觸發備案。

## ⚔️ 【演武場：從冒險者到勇者辛梅爾】

### 招式示範：短路判斷實戰
[展示「繁瑣判斷（Before）」與「極簡開關（After）」的對比。]

#### ❌ 冒險者：寫不完的 if/else
```javascript
let nickname;
if (user.name) {
  nickname = user.name;
} else {
  nickname = '無名勇者';
}

// 條件渲染更痛苦
if (isLoggedIn) {
  showProfile();
}
```

#### ✅ 勇者辛梅爾：極簡一行搞定
```javascript
// 1. 設定預設值 (確保只有 null/undefined 才生效)
const nickname = user.name ?? '無名勇者';

// 2. 條件執行 (只有登入才顯示)
isLoggedIn && showProfile();

// 3. 多重保險
const power = monster.strength || hero.basePower || 10;
```

> **導師講評：** 你看，這種寫法不僅能省下大量行數，更重要的是它定義了資料的「流向」。老練的勇者一眼就能看出你的邏輯備案是什麼。

#### ⚠️ 【實戰雷區：0 與空字串的冤獄】
> 在 JS 中，`0`、`""`、`NaN`、`false` 都被視為 Falsy。如果你用 `||` 設預設值，這些值都會被自動略過。請確認你的業績是不是真的「沒達成」，還是讀者本來就是領「0」分獎勵？請優先使用 `??`。

## 🏰 【勇者精英課：邁向職人的進階架構】
[在 React 與現代框架中，你將頻繁使用 `&&` 來控制畫面的顯示與否（例如：`isLoading && <LoadingSpinner />`）。掌握短路判斷，是從「操作 DOM 的士兵」轉型為「架構邏輯的將軍」的第一步。]

## 📝 【夥伴筆記：今日修煉精華】
##### *這份筆記是你的隨身護身符，卡關時看一眼，真相就在裡面。*
- **&&**：前面的 True 了，才執行後面。
- **||**：前面的 False 了，才拿後面墊背。
- **??**：精準守衛，只有 null/undefined 才啟動備案。
